# EFES-v2-final：实施与论文统一文档

## 0. 文档目的

这份文档是 **EFES-v2 的最终统一实施说明**。目标不是继续在旧 EFES 上局部修补，而是直接给出一条能够同时指导：

* 代码重构
* 训练与调试
* 指标与日志
* 论文方法与实验写作

的单一主线。

本文档默认采用以下原则：

1. **新开 EFES-v2 独立路径**
2. **旧 EFES / V5 / V6 只保留为对照，不回写行为**
3. **优先修正语义与训练闭环，不先追求大规模实验**
4. **把 EFES-v2 定义成一个 trainable intervention-aware self-diagnosis system**
5. **首版只实现 P0 + P1，P2 留接口，不作为首版强依赖**

---

## 1. 一句话定义

**EFES-v2 是一个可训练的具身自诊断与恢复框架：它将宏观学习目标、宏观异常证据和宏观不确定性三分离，并通过可微的恢复路由，把诊断直接转化为恢复模式选择。**

中文论文可用版本：

**EFES-v2 不是再叠加一个异常分数，而是把宏观学习目标、宏观异常证据与宏观不确定性显式分离，并通过可训练的恢复路由，将自我诊断直接映射为恢复行为选择。**

---

## 2. EFES-v2 的哲学内核

### 2.1 核心立场

EFES-v2 的“self”不被定义为一个孤立的内部隐变量，而被定义为：

**身体状态与环境状态持续耦合后，在系统内部形成的可操作变化状态。**

也就是说：

* 肉体：agent 当前的行动能力、历史动作、控制状态、belief/prior 结构
* 环境：当前观测、拓扑结构、候选空间、frontier、位置推进约束
* self：身体与环境耦合变化后在内部形成的 meta-state
* diagnosis：发现耦合关系发生异常变化
* recovery：对这种异常变化做干预选择

### 2.2 论文外部安全表述

论文中不要直接使用“意识”“自我意识”“物质意识”等词作为主 claim。
推荐外部表达：

* self state arises from ongoing body-environment coupling
* diagnosis is driven by changes in coupling across micro and macro scales
* recovery is a learned intervention over coupling failures

中文可写为：

* 自我状态来源于持续的身体—环境耦合
* 异常由微观与宏观耦合关系的变化驱动
* 恢复是对耦合失配的学习型干预选择

---

## 3. 当前旧 EFES 的四个根问题

EFES-v2 的建立是为了一次性修正旧 EFES 中已经坐实的四个根问题。

### 3.1 macro 训练目标与诊断信号混用

旧版中，heteroscedastic Gaussian NLL 同时被用作：

* `node_loss`
* `C_macro`

这导致：

* `node_loss` 可变负
* `C_macro` 不再是稳定异常量
* `A_t` 会被一个语义漂移的宏观通道污染

### 3.2 macro 使用的 feature space 不一致

旧版中：

* topo bank 存的是压缩特征
* 但 `C_macro` 和 `topo_novelty` 却仍基于 raw `node_feat`

这造成：

* retrieval 在 compressed space
* memory 在 compressed space
* novelty/compare 却在 raw space

属于第二层语义错位。

### 3.3 phase2 不是有效联合训练

旧版 trainer 中，phase2 虽然名义上解冻了部分 ETP 参数，但 policy 主前向长期包在 `torch.no_grad()` 中，导致：

* 参数 `requires_grad=True`
* 但前向图未构建
* 梯度不能真实回到解冻模块

因此 phase2 的“联合微调”不成立。

### 3.4 recovery decision 基本不受 `L_plan` 约束

旧版中：

* mode 先由 hard rule 决定
* 再通过 `.item()` 进入 Python 分支
* `_apply_recovery()` 生成 hard masked logits

这意味着：

* `plan_loss` 很难反传到 mode selection
* 恢复分支更多是规则系统，不是被导航结果训练出来的干预选择器

---

## 4. EFES-v2 的总设计原则

EFES-v2 的设计必须同时满足以下 6 条原则：

1. **macro 三分离**
   训练损失、诊断量、不确定性必须彻底拆开。
2. **统一 feature space**
   macro bank / retrieval / novelty / diagnosis / predictor 全部在 compressed node feature space 进行。
3. **monitor 只接诊断量，不接训练损失，不直接接 uncertainty**
4. **phase1 就训练 recovery router**
   不再把 recovery 训练延后到 phase2。
5. **phase2 必须是真联合训练**
   不是“参数可训练”，而是“解冻模块实际有非零梯度”。
6. **BELIEF\_UPDATE 必须有独立动作语义**
   不再与 PROCEED 共用完全相同的 candidate-space 行为。

## 8. EmbodiedSelfStateV2

### 8.1 目标

Self state 不再仅由：

* 上一时刻 self
* instruction
* 上一时刻 posterior

生成，而是要显式吸纳身体与环境耦合证据。

### 8.2 输入

建议分为三类 token：

#### A. body tokens

* `prev_action_emb`
* `prior_var_mean` 或 `prev_prior_alpha`
* `revisit_count`
* `loop_evidence`
* `stuck_evidence`

#### B. environment tokens

* `x_t` 或当前 observation summary
* `candidate structure summary`
* `frontier_size`
* `topo_novelty`
* `macro_valid`
* `progress_gap`

#### C. history/instruction tokens

* `prev_self`
* `prev_z`
* `instruction tokens`

### 8.3 输出

* `s_t`
* `progress_t`
* `attn_entropy`
* 可选 `self_debug_tokens`

### 8.4 定义

论文里可写：

[
s\_t = f\_{\\text{self}}(b\_t, e\_t, h\_{t-1}, I)
]

其中：

* (b\_t)：body state
* (e\_t)：environment state
* (h\_{t-1})：historical self state
* (I)：instruction context

保留微观时序失配建模，用于给出：

* `c_micro_diag`

### 9.2 输出

至少包括：

* `h_t`
* `z_post`
* `mu_pri`
* `std_pri`
* `mu_post`
* `std_post`
* `c_micro_diag`

### 9.3 训练语义

仍可沿用 KL / free-nats 逻辑。
微观分支不做大改，重点在于：

* 保持数值稳定
* 与 macro 分支清晰解耦
* 向 router 提供微观失配趋势信号

## 10. MacroSurpriseV2

### 10.1 目标

macro 分支彻底三分离，并统一到 compressed node feature space。

### 10.2 输入

* `node_feat`
* `topo_context`

### 10.3 中间变量

[
x\_{comp} = \\text{compress}(node\_feat)
]

[
\\mu\_{pred}, \\sigma^2 = \\text{predict}(topo\_context)
]

### 10.4 输出

固定只输出：

* `x_comp`
* `mu_pred`
* `sigma2`
* `node_nll_loss`
* `c_macro_diag`
* `u_macro`
* `topo_novelty`

### 10.5 公式

训练损失：

# [

L\_{node}^{nll}

\\frac{1}{2}
\\operatorname{mean}*d
\\left(
\\frac{(x*{comp}^{sg}-\\mu\_{pred})^2}{\\sigma^2}
+
\\log \\sigma^2
\\right)
]

诊断量：

# [

C\_{macro}^{diag}

\\operatorname{mean}*d
\\left(
\\frac{(x*{comp}^{sg}-\\mu\_{pred}^{sg})^2}
{\\operatorname{clip}(\\operatorname{stopgrad}(\\sigma^2), s\_{min}^{diag}, s\_{max}^{diag})}
\\right)
]

不确定性：

# [

U\_{macro}

\\operatorname{mean}*d
(\\log \\sigma^2*{sg})
]

### 10.6 硬性约束

* `node_nll_loss` 可正可负
* `c_macro_diag >= 0`
* `u_macro` 不直接进入 `A_t`
* novelty 与 bank comparison 也必须在 compressed space 完成

## 11. TopoStateBankV2

### 11.1 bank 内容

每个条目至少包含：

* `vp_id`
* `compressed_feat`
* `step_index`

### 11.2 更新 mask

`build_update_mask()` 同时考虑：

* `bank empty`
* `cur_vp changed`
* `candidate_count >= decision_threshold`
* `timeout >= K`
* `topo_novelty >= novelty_threshold`
* `cooldown satisfied`

### 11.3 策略

* `bank empty`：强制触发
* `cur_vp changed`：强制触发
* `candidate_count`：受 cooldown 约束
* `timeout`：受 cooldown 约束
* `topo_novelty`：受 cooldown 约束

### 11.4 目标

`macro_valid_ratio` 不再接近逐步触发，而是只在：

* 关键节点
* 决策点
* 长时间未推进的兜底点

触发。

## 14. RecoveryRouterV2

### 14.1 核心定位

这是 EFES-v2 的关键创新模块。

### 14.2 输入

建议固定为：

* `s_t`
* `A_t`
* `pi_t`
* `c_micro_diag`
* `c_macro_diag`
* `u_macro`
* `progress_gap`
* `frontier_size`
* `revisit_count`
* `loop_evidence`

### 14.3 输出

* `mode_logits`
* `mode_probs`
* `alpha_prior`
* `alpha_progress`

### 14.4 mode 集合

固定四类：

* `PROCEED`
* `EXPLORE`
* `BACKTRACK`
* `BELIEF_UPDATE`

### 14.5 训练期

训练时：

[
p(m|u\_t)=\\operatorname{softmax}(mode\_logits / T)
]

然后每个 mode 产生一套 mode-specific logits：

[
\\ell\_t^{(m)}
]

融合为：

# [

\\ell\_t^{fused}

\\log \\sum\_m p(m|u\_t)\\exp(\\ell\_t^{(m)})
]

最终 `L_plan` 使用 `fused_logits`。

### 14.6 推理期

推理时：

* `mode = argmax(mode_logits)`
* 再做硬模式执行

### 14.7 启动扶手

首版必须加入一个 bootstrap 监督：

# [

L\_{router}^{boot}

\\operatorname{CE}(mode\_logits, pseudo\_target)
]

其中 `pseudo_target` 可来自旧 EFES 的规则模式。
作用：

* 训练前期给 router 骨架
* 后期权重退火到 0

## 15. ModeActionProjectorV2

### 15.1 目标

为每个 mode 产生 mode-specific candidate semantics。

### 15.2 必须实现的语义

#### PROCEED

* strict candidate set
* 标准前进决策

#### EXPLORE

* 扩展 frontier
* 放宽候选空间

#### BACKTRACK

* 回退或 stop override
* 可结合历史 backtrack score

#### BELIEF\_UPDATE

必须拥有独立动作语义，不允许和 `PROCEED` 共用完全相同的 strict-mask。

建议语义：

* 放松 visited/strict 一层
* 保留 frontier 偏好
* 同时启用 `alpha_prior`
* 同时启用 `alpha_progress`

### 15.3 命名约束

如果做不到独立动作语义，不要叫 `BELIEF_UPDATE`。
应改名为 `LATENT_RECALIBRATE`。
但 EFES-v2-final 默认要求你把真正的 `BELIEF_UPDATE` 做出来。

## 17. 训练方案

## 17.1 Phase 1

* ETP backbone 全冻结
* policy 前向可用 `no_grad()`
* 但 **router 已经参与训练**
* `fused_logits` 已经参与 `L_plan`

### 17.2 Phase 2

* 解冻指定 ETP 子模块
* policy 主前向统一建图
* 冻结部分仅靠 `requires_grad=False`
* 解冻子模块切回 `train()`
* 继续用 `fused_logits` 训练

### 17.3 总损失

固定为：

# [

L

L\_{plan}^{fused}
+
\\lambda\_{kl} L\_{micro}
+
\\lambda\_{node} L\_{node}^{nll}
+
\\lambda\_{pi} L\_{pi}^{cal}
+
\\lambda\_{boot} L\_{router}^{boot}
]

### 17.4 说明

* 首版不引入 failure attribution loss
* 首版不引入额外 contrastive 宏观损失
* 先把语义与闭环训稳

## 23. 论文主线更新

## 23.1 论文一句话主张

推荐主张：

**EFES-v2 将具身导航中的自我诊断从单一异常分数升级为一个可训练的干预选择问题。**

## 23.2 三点贡献写法

建议写成：

1. 提出基于身体—环境耦合状态的自我表征与双尺度诊断框架。
2. 提出宏观学习目标、宏观异常证据与宏观不确定性的三分离机制。
3. 提出可微恢复路由，将诊断结果直接转化为恢复模式选择。

## 23.3 不要过强的说法

先不要强写：

* agent 知道自己为什么错了
* 具身自我意识
* 通用自我认知
